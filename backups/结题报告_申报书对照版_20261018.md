## 一、项目研究工作总结

本项目围绕"如何将阴影的物理先验与通用视觉基础模型 SAM 相结合，实现高精度、自动化的遥感影像阴影检测"这一核心问题展开。项目按照"物理先验引导 + 基础模型适配"的技术思路，完成了方法框架搭建、算法实现、参数高效微调（含 LoRA 微调）、以及基于公开数据集 AISD 的定量实验验证。

在**按原始大图重划的无泄漏划分**上，LoRA 微调 SAM 的数值结果高于全监督 U-Net / SegNet 基线（**3 seed 均值 IoU 0.7990 ± 0.0101** vs U-Net **0.7547 ± 0.0028** / SegNet **0.7382 ± 0.0044**；单值 0.7878/0.8075/0.8016）；3-seed 配对检验支持该数值优势（场景级 IoU 差 **+0.0498 / +0.0655**），但仍受**测试集仅 21 个独立场景、效应量随聚合口径大幅变化、未做多重比较校正**限制，**不宣称 SOTA/显著超越**（详见 3.2 附注与 3.3）。

## 二、技术方案与实现

### 2.1 总体框架

本项目构建了一条"物理粗提取 → 自动提示 → 精细分割"的端到端阴影检测流程，并通过参数高效微调（特别是 LoRA 微调）使 SAM 适配遥感阴影场景。核心代码位于项目目录下（`methods.py`、`train_adapter_v4.py`、`evaluate_lora.py`、`run_experiment.py`、`eval_shadow.py` 等）。

### 2.2 关键模块

1. **增强物理粗提取**：对灰度影像做 CLAHE 自适应直方图均衡化增强暗部细节，反相后采用 Otsu 自动阈值分割，再用形态学开运算去除细小噪声，得到高召回率的阴影候选区域。

2. **自动提示生成**：从候选区域提取连通域包围框作为框提示，输入 SAM。

3. **LoRA 参数高效微调（核心成果）**：在 SAM 图像编码器（ViT-B）每个注意力层的 qkv、proj 上挂 LoRA（低秩适配，rank=8），冻结原始权重、仅训练 LoRA 矩阵（0.44M）+ 掩膜解码器 + 提示编码器（共 4.51M 可训练参数，占模型总参数约 4.8%）。训练时用 Focal Loss + Dice 损失、点/框双提示、水平翻转增强、余弦学习率、混合精度（AMP）加速。该做法使冻结的编码器也学到遥感阴影特征，是"Adapter 微调"的正规实现。

4. **方向一致性探索**：系统研究了方向先验的**四种注入方式**（几何过滤、方向点提示、方向点训练、**方向 Adapter 条件注入**），得到诚实结论（见 3.3）。

5. **定量评估模块**：实现 IoU、BER、F1、OA、Precision、Recall 六项指标，支持批量评测与消融分析。

### 2.3 设计说明：为何采用二值阴影掩膜而非多类掩膜

本项目所有监督信号与评估指标均建立在**二值阴影掩膜**（每像素：阴影 / 非阴影）之上。这一选择不是技术妥协，而是由**任务定义**决定的，理由如下：

1. **任务定义即二分类**。"阴影检测"要回答的问题是"该像素是否属于阴影"，而非"该像素属于何种地物"。多类掩膜会引入与任务无关的类别区分（如"建筑 / 道路"），使模型容量被非目标语义占用。

2. **评价指标以二类混淆矩阵为前提**。本项目使用的 BER 定义为 `0.5 × (假阳性率 + 假阴性率)`，其成立前提正是"前景 / 背景"两类；IoU、F1 亦然。改用多类会使指标需重新定义，且**无法与现有文献结果比较**。

3. **保证与公开基准可比**。AISD 的标注为二值；本项目用于跨数据集验证的 RSISD（SARU 提出）经核验其掩膜同样为二值（像素值仅 {0, 255}）。主流的阴影检测基准（AISD、SBU、ISTD 等）均采用二值标注——沿用同一表示法是结果可比性的前提。

**多类表示法确实更有价值的一处情形**：若标注中包含"水体 / 深色植被 / 深色路面"等**非阴影的暗色地物**类别，模型可直接学习"该像素虽暗，但属于水体而非阴影"这一判别，这对缓解**异物同谱**（阴影与低反射率地物混淆）有明显帮助。其代价是标注成本大幅上升（需标注全图所有地物类别，而非仅阴影），且现有公开数据集均无此类标注。

**本项目的处理方式**：不改动 GT 的表示法，而是在模块②（方向引导提示生成）中，以**规则式伪阴影剔除**近似多类标注的判别能力——依据 HSV 色彩判据，在推理阶段将绿化（植被色相 + 高饱和度）与水体（水体色相 + 低饱和度）区域判为伪阴影并予以剔除，同时结合方向一致性约束排除方向杂乱的暗色地物（详见 2.2 与 3.3）。

> **诚实的边界**：该做法是**规则近似**，其判别力弱于真正的多类监督，且阈值依赖色彩统计、对传感器与季节变化敏感；它在本项目中的实际增益已在 3.3 中如实报告（方向提示方法的收益有限）。把"非阴影暗色地物"作为显式类别纳入监督，是本项目的后续研究方向之一。

## 三、实验与结果分析

### 3.1 数据集与设置

- **数据集**：AISD（Aerial Imagery Dataset for Shadow Detection）。AISD 自带划分为 Train412 共 412 张、Val51 共 51 张、Test51 共 51 张；这 412 张训练子图来自 **105 张原始大图**（多尺度航空影像，约 256~1688 像素，逐像素阴影标注）。
- **⚠️ AISD 自带划分存在同源泄漏**：AISD 自带 Test51 的 43 个原始大图基名中，有 **42 个同时出现在 Train412**（仅 `vienna12` 独立）。即测试场景与训练场景大面积重叠（同传感器、同太阳方位、相邻裁剪），在该划分上取得的指标**系统性偏高**，不能作为干净泛化能力汇报。
- **划分口径（本项目采用两个口径，分别报告）**：
  - **主口径（无泄漏）**：参考 `train_lora_leakfree.py`，按**原始大图基名**整组划分为 **68 训练 / 16 验证 / 21 测试**（原图数），对应子图 **262 / 58 / 92** 张；三集基名**互不重叠**。所有深度方法（LoRA-SAM / U-Net / SegNet）在**同一划分**上重训与评估。
  - **AISD 自带划分（Train412 / Val51 / Test51）**：**含同源泄漏**，仅用于与项目早期文档、历史数字对齐，**不与主口径结果横向比较**。
- **模型**：SAM ViT-B（vit_b，358MB），NVIDIA RTX 4060（8GB）。
- **微调设置**：LoRA 微调编码器 + 掩膜解码器 + 提示编码器（4.51M 可训练参数），AdamW + 余弦学习率，Focal Loss + Dice 损失，点/框双提示训练，水平翻转增强，AMP 混合精度。
- **评估协议**：统一调用 `eval_shadow.compute_metrics`，逐图计算再取均值；六项指标 IoU / BER / F1 / OA / Precision / Recall。
- **选模型口径**：**仅在验证集上按 IoU 选最佳权重（best-val），测试集只用于最终报告、绝不参与选模型**。主口径下三个深度方法**统一采用 best-val 检查点**，口径一致、可横比。
- **推理口径**：SAM 类方法用**框提示**（由输入图自身的增强 Otsu 自动生成，**不读 GT**）；CNN 类方法用 **512×512 整图**输入（各自架构的自然输入）。
- **测试方式**：全自动，无人工干预。

> ③ **† Mask R-CNN 的分辨率不对称（必须一并声明，不得删除）**：主行已改用 **`min800/max1333`**（torchvision 默认）的复跑结果，子行为 `min512/max800`（原跑法）。但**复跑只缓解了一半问题**——本次仅把**模型内部** min/max 提到默认，**输入仍固定 `cv2.resize(..., (512,512))`**，即把**已降采样的 512 图再上采样到 800**（torchvision `GeneralizedRCNNTransform`），**不恢复任何原始细节**，且未跑 torchvision 完整默认 pipeline（原始图短边 800 / 长边 1333）。而主方法走 SAM 的 `ResizeLongestSide(1024)`，作用在**原图**上。**故相对主方法 1024 的不对称依旧存在**，属**部分缓解**，**不得表述为"分辨率偏置已消除"或"对比已公平"**。复跑使差值由 0.0548 收窄到 **0.0496（seed-0 敏感性）**，**只解释了约 9%**。3v3 差值为 **+0.0598（场景 +0.0602）**，仍受分辨率不对称限制。
> 　另：本次 test 上的 **+0.0052 落在逐图噪声内**（逐图配对差 sd 0.0291、**t≈1.70 未达显著**、**逐图 46 胜 46 负**）→ **只能写"数值上略高"，不得写"改进/提升"**。
> 　补充：BER 由 0.0965 变 0.0968（seed-0 敏感性；变幅 0.01σ）属噪声——BER 被海量背景 TN 主导、对边界不敏感，与本项目"**BER 稳 / IoU 敏感**"的既有认知一致。
> ④ **C3I 两行必须同列（不得只报其中一个）**：`methods.py` 的 `mask_c3i` 内含一段**本项目自加**的启发式（前景占比 >40% 时整体取反），**不是 C3I 原方法的一部分**。实测该启发式在 92 张测试集上触发 **61 张**，去掉后 **61/61 全部变好、0 张变差**（在本数据上 100% 有害）。故**主行为去除启发式的 0.4564**，末行为保留启发式的 0.1765（**仅供口径对照**）。**若只报 0.1765 会把本项目代码的缺陷误记为 C3I 方法的性能**。
> ⑤ **Mask R-CNN 协议说明**：实例由 GT 掩膜连通域（`area ≥ 200`）导出，评估时保留 `score ≥ τ` 的实例、软掩膜 `>0.5` 取并集、**最近邻**缩放回 GT 尺寸。`τ` 与最佳 epoch **仅在验证集(58 张)上选**（选用 τ=0.05，落在网格下界且与 τ=0.1 近乎并列 → 阈值选择稳健性有限）。收敛判据已落盘（`results/maskrcnn_leakfree_val_curve.csv`，最佳 val IoU 出现在 epoch 30、末次评估 epoch 60，曲线见顶 → **基线非欠训**）。
> ⑥ **公平性对照说明**：本项目主方法的框提示来自 `mask_enhanced`（Otsu+CLAHE 粗提取），**不读 GT**；Mask R-CNN 亦为 COCO 预训练 + 全自动推理。两者均**全自动、无 GT 泄漏**。
> ⑦ **与文献可比性**：本表使用**自建的无泄漏重划划分**，测试集 ≠ AISD 自带 Test51，因此本表数字**不能与文献中 AISD 上的报数直接横向比较**（见第五节局限⑤）。

### 3.3 结果分析

1. **无泄漏划分下，LoRA 微调 SAM 数值上高于全监督 CNN 基线**：IoU **0.7990 ± 0.0101**（3 seed）vs U-Net **0.7547 ± 0.0028** / SegNet **0.7382 ± 0.0044** / Mask R-CNN **0.7392 ± 0.0039**，BER **0.0612 ± 0.0027** vs **0.0860 ± 0.0091** / **0.1003 ± 0.0020** / **0.0955 ± 0.0042**。这说明"修复增强 bug + 去除同源泄漏"之后，LoRA 的领先**不是泄漏造成的假象**。3-seed 配对检验：图级 IoU 差 −0.0443（U-Net）/ −0.0608（SegNet）/ −0.0598（Mask R-CNN），场景级 −0.0498 / −0.0655 / −0.0602；BER 方向一致。**但必须同时声明**：测试场景仅 21 个、未做多重比较校正、效应量随聚合口径大幅变化、Mask R-CNN seed-0 clean_run 未验证、LoRA seed-1 resumed、Mask R-CNN 分辨率不对称仍在 → **配对检验支持数值优势，但不升级为"显著优于/超越全监督/SOTA"**。

2. **同源泄漏对指标的影响可量化**：同一 LoRA 方法，AISD 自带划分（含泄漏）IoU 0.8393，无泄漏划分 0.7878（**seed-0**，为与自带划分那次 run 同 seed 对照），**相差 0.052**。这从实证上说明，AISD 自带 Test51 上的报数因测试场景与训练场景重叠而**系统性偏高约 5 个 IoU 点**——这也是本项目重做评估基座的核心动因。

3. **"零样本 → 冻结微调 → LoRA 微调"的清晰递进**（**自带 Test51 口径**，同表内可比）：零样本 SAM 0.234 → 冻结编码器微调 0.717 → LoRA 微调 0.839（该行含泄漏，见附表）。每一步的增益都验证了"基础模型需领域适配"的判断；其中"冻结 → LoRA"的增益在**无泄漏口径**下同样成立 —— 冻结编码器版的**无泄漏**重训**已补做**（`train_frozen_leakfree.py`，与 LoRA 版同一划分/同一轮数/同一日程，**唯一差异 = 是否对编码器做 LoRA 适配**），IoU **0.562110**（单 seed），对照 LoRA **seed-0** 的 **0.787821**。
   ⚠️ **口径纪律**：上句的 **0.717 是自带 Test51（含同源泄漏）口径**、**0.562 是无泄漏口径**，**二者不可横比**；冻结版目前**仅单 seed**。

4. **方向先验的可辨识度：一次量化的系统探索**。本项目对"方向先验能否提升阴影检测"做了系统的量化研究，结论如下（全部有落盘证据）：

   **（a）模块② 方向提示的三类注入方式**：几何方向过滤（提升 Precision 但损失 Recall，净 IoU 略降）；方向点提示（旋转框顶点/主轴采样）优于无方向质心点提示（**0.714 vs 0.690，+0.024**）但低于框提示（0.717）；方向点训练受训练策略限制未达预期。→ 在 SAM 框架下，框提示本身已编码强空间先验。
   **（a'）模块③ 方向 Adapter 条件注入**（第四类，见 3.3 末与"问题与不足"第 3 条）：将方向向量作为条件注入提示编码器；ΔBER −0.0038、ΔIoU −0.0005，且**随机方向训练的对照复制出同量级 ΔBER**。

   **（b）方向回归头（连续方位角）的表现**：以 ResNet-18（加载自监督翻转判别预训练骨干）回归全局阴影方向，在无泄漏划分下验证 **28.29°/28.37°**、测试 **29.34°/28.56°**（无/有随机裁剪两 run），**未达 <20° 的可用门槛**。对照基线：**常数预测器（对所有图恒预测同一方向）29.83°，随机水平 45°**——即**模型仅比"什么都不学"好约 1.5°**。消除"随机裁剪 vs 整图标签"输入-标签错配后（训练误差由 23.82° 降至 **10.42°**），验证/测试误差**并不下降**，说明未达标非该错配所致。

   **（c）方向标签一致性的探针分析**（本项目提出的诊断方法，不训练、可复现）：对 4 种方向估计量（最小外接矩形长轴、PCA 主轴、阴影边界梯度、阴影质心→邻域最亮区连线）计算逐图一致性 R：观测均值 **0.23~0.37**，而**样本量匹配的随机基线为 0.212**。其中三个几何类估计量超出 +0.12~0.15，但**物理方位代理（指向光源的连线）仅超出 +0.015**；更换估计量也未能改善（最优仅优于现状 0.01）。

   **（d）DTICT 噪声抑制的复现与消融**：按导师论文（祁昆仑 等, 2025）的思路，本项目实现了一版 **DTICT**（双网络 Co-teaching 互选 + 方向一致性门；后者依据原图/翻转图高层特征的余弦相似度剔除噪声样本，门限由训练集自身分位数预注册确定）。实测：一致性门剔除 **54/262（20.6%）** 判为噪声的图；**开启与关闭 DTICT 的验证翻转准确率均为 1.0000**（消融表 `results/direction_dtict_ablation.csv`）。
   **说明**：该结果**不代表 DTICT 无效**——翻转判别这一**代理指标已饱和**（全项目多次达到 1.0000），在该指标上无法分辨差异；DTICT 的收益需在**未饱和的下游任务**上才能度量。另需声明：论文未公开 DTICT 完整超参，本实现是**按原理的简化重构，非逐行复现**。

   **结论与定位**：AISD 影像上"整图单一阴影方向"这一标签的**可辨识度有限且成因未定**——所观测到的一致性**不足以判定来源于太阳方位角共享**（亦可能来自城市建筑/街道网格朝向一致）。本项目据此**未将方向模块作为主方法**，而是作为"对方向先验在遥感阴影检测中可辨识度的量化探索"如实报告：**负/中性结果与量化诊断同样是方法学产出**。主方法仍为无泄漏划分下的 LoRA-SAM（见 3.2）。
   **限制**：单 seed；验证集仅 16 个独立场景；成因（标签噪声下限 / 数据量 / 模型容量 / 优化）未加区分。

5. **稳定性**：无泄漏划分下，LoRA 的逐图 IoU 标准差（0.0686，**总体 sd**）小于 SegNet（0.0964）与 U-Net（**0.0928**），BER 标准差（0.0221）亦最小，说明本方法在**数值上与波动上**均表现较好——但同样**未做显著性检验**、且受小样本（21 场景）限制，不作稳定性显著性的结论。

## 四、主要创新点

1. **LoRA 参数高效微调释放基础模型潜力**：仅训练约 4.8% 参数（含 0.44M LoRA 参数）。
   - **干净单变量对照（推荐引用）**：**同一提示函数、同一 92 张测试集**下，原生 SAM（**未微调**）IoU **0.347968** → 微调后 **0.7990 ± 0.0101**（3 seed；单值 0.7878 / 0.8075 / 0.8016）。**两者只差"是否微调"**；**逐图 92/92 张在三个 seed 上均为微调更高**。
     **配对均差**（逐图差取均值；与"两均值之差"等价）：**seed-0 +0.4399 / seed-1 +0.4596 / seed-2 +0.4536；3 seed 平均 +0.4510**（seed-0 的差 std 0.141）。
     ⚠️ **引用纪律**：配对差**必须写明对应哪个口径** —— **seed-0 的 +0.4399 不可与 3-seed 均值 0.7990 并置**；若采用 3-seed 均值作 headline，配对差应写 **+0.4510**。
     ⚠️ **不得**全归因于 LoRA —— 被微调的参数含 **LoRA adapter + prompt encoder + mask decoder**（共 4.51M），非仅 LoRA；亦**不得**写"提升/改进"。
   - **零样本 AMG 对照（引用须带两因素声明）**：无泄漏划分下，零样本 SAM（AMG 自动掩膜 + 暗度筛选）IoU **0.2663** → 微调后 **0.7990 ± 0.0101**。**但该对比同时改变了两个因素**（提示方式：AMG 自动掩膜 → 框提示；权重：零样本 → 微调），因此**不能把全部差距归因于"微调"**（详见 3.2 注⑩）。

2. **物理先验与基础模型的融合**：将阴影的光谱（暗、偏蓝）物理先验转化为自动框提示，实现全自动、无人工干预的阴影检测。

3. **"零样本 → 冻结微调 → LoRA 微调"的完整技术演进**：清晰展示了通用基础模型适配遥感垂直领域的有效路径。

4. **诚实、可复现的实验体系**：标准数据集 + 六项指标 + 消融 + 零样本/冻结微调/LoRA/U-Net 对比的完整评估流程，代码与结果可复现；并**主动排查并修复了AISD 自带划分的同源泄漏与基线脚本的增强 bug**，把评估基座重建到无泄漏划分上。

## 五、存在的问题与不足

> 本节按**申报书承诺 → 实际交付**逐条列出。凡未实现/未做的，**一律如实写出**，不以口径或措辞淡化。

> **实际实施路径（总括）**：本项目实际走的闭环是「**增强物理粗提取（CLAHE + Otsu + 形态学） → 连通域框提示 → LoRA 微调 SAM 推理 → 掩膜合并与指标评估**」。
> 对照申报书"**数据准备—特征提取—提示构建—模型推理—结果优化**"五环节：**四环未按原设计实现** —— **数据准备**（辐射/几何校正、三种数据增强均未做，见第 **11** 条）、**特征提取**（双流架构未实现，第 **4** 条）、**提示构建**（实际用框提示而非方向感知提示，第 **2** 条）、**结果优化**（特征融合与抑制未实现，第 **4/5** 条）；**仅"模型推理"一环相符**。
> 即：**闭环是通的**（**指管线端到端可运行、可评估、可输出矢量**），**但五个环节中有四环与申报书原设计不同**。

1. **申报书模块① 自监督阴影方向感知网络**：**已实现**（ResNet-18 翻转判别自监督预训练 + 方向回归头），但**未达可用门槛** —— 回归头验证 **28.29/28.37°**、测试 **29.34/28.56°**，对照常数预测器 **29.83°**、随机 45°（**单 seed；该批数字未经单独送审**）。
   ⚠️ 申报书原文**未规定角度门槛**；`<15~20°` 是项目内部判据（见 `执行顺序与应急预案.md`）。

2. **申报书模块② 的"射线投射采样法 + 扇形搜索区域"**：**代码已实现**（`direction_prompt.py` 的 `project` 分支即该算法的**直译实现**），**但仅在 oracle（GT）方向口径下跑过；真实（回归）方向口径从未跑、从未作为主方法**。主方法仍用框提示。

3. **申报书模块③ 方向特征 Adapter**：**已实现并完成训练与评估**（预期为"未实现"，实际已补做）。结果：ΔBER **−0.0038**（配对 t=−7.55）、ΔIoU **−0.0005**（无净变化）；且**用无信息随机方向训练出的对照 adapter 复制出同量级 ΔBER**（跨 adapter 配对 t=−1.00 / −0.11）→ **该 ΔBER 效应不依赖于方向输入的内容**。
   ⚠️ 限定：单 seed；92 张 / 21 独立场景；**仅针对"方向通道开关"这一 ΔBER 效应，与主方法 0.7878 无关**（主结果从未包含方向模块）；**不代表"方向先验无效"**。

4. **技术路线"双流特征提取架构"与"特征融合与解码"**：**未实现**。具体缺三样：① **物理流（方向网络）未与视觉流并联**；② 申报书点名的 **Feature Aggregator**（Cross-Attention 融合 + 多尺度 DownConv/FusionConv）**未实现**；③ **方向适配器加权抑制误检**未实现。实际流程 = 增强粗提取 → 框提示 → LoRA-SAM。

5. **损失函数 IoU Loss + Boundary Loss**：**未实现**（该项经人类决定不做，已归档 `archive/f3_cut_20261016/`）；实际使用 **Focal Loss + Dice Loss**。

6. **SOTA 对比 ShadowFormer**：**未做**。这里存在**方法定位问题** —— ShadowFormer 属"阴影**去除**"，与阴影**检测**的指标不可比，据申报书原文直接对比并不成立。替代方案（SARU 真 SOTA）**未复现**：其仓库无网络定义代码。

7. **WHU Building Dataset 作辅助测试集**：**未做**。**且申报书此处属用途错位** —— WHU Building **无阴影标注**；导师论文（祁昆仑 等, 2025）是将该数据集用于**无标签自监督预训练**，而非"验证阴影泛化的测试集"。本项目改用 **RSISD**（真阴影检测基准）作跨数据集验证（IoU 0.7842，n=200）。

8. **算力配置实述**：申报书"可行性分析"称"实验室配备高性能 GPU 服务器（如 NVIDIA RTX 3090/4090）"；实际**全部实验在 RTX 4060 Laptop（8GB 显存）**上完成。

9. **学术论文与软件著作权**：**论文尚未产出**；软著说明书初稿数字滞后（为无泄漏 **seed-0** 口径），须按 **3-seed headline（0.7990 ± 0.0101）** 重做并补源程序文档后提交。

10. **软件原型**：`shadow_extract.py` 已实现"**输入影像 → 输出阴影矢量**"（GeoJSON / Shapefile，含地理参考处理）。端到端验证**已脚本化并落盘**（`verify_shadow_extract.py`、`logs/verify_shadow_extract_*.log`），三项结果：
    - 无地理参考输入（AISD `chicago30_sub1.tif`，512×512）：42 个多边形、全部为像素坐标；**矢量↔栅格往返面积差 −5 像素 / 46614（0.0107%）**；栅格化后 IoU **0.843834**，对照管线自身 **0.845274**（差 −0.001440，为 `simplify(1.5px) + min_poly_area(64)` 的预期代价）。
    - Shapefile 分支：`.shp/.shx/.dbf` 产出完整，读回 42 要素。
    - 地理参考分支：顶层正确写出 `crs`，`coord_system="map"`，坐标落在 `transform` 推算范围内。
    ⚠️ **规模与代表性限制**：以上**仅在一张 512×512 AISD 子图 + 一个合成地理参考样本上验证**；**地理参考分支的样本是合成的**（真实子图 + 伪造 CRS/transform），**只能证明"CRS/坐标写出路径"走通，不代表真实遥感产品的 CRS/轴序已验证**。**未经更大规模、多传感器实测。**

11. **申报书"技术路线"第 1 步「数据预处理与增强模块」**：**未按原设计实现**。申报书原文要求"对高分辨率遥感影像进行**辐射校正与几何校正**"，并使用"**对比度调整、随机裁剪、色彩抖动**"扩充训练样本；实际 —— **辐射校正 / 几何校正未做**（AISD 为已处理数据）；训练增强**只有水平翻转**（`train_adapter_v4.py:143`，50%）与点/框提示混合（`:150`），**申报书所列三种增强均未做**。
    ⚠️ 不要把 `mask_enhanced` 的 CLAHE 算作训练增强 —— 那是**推理期的物理粗提取**，不是数据增强。
