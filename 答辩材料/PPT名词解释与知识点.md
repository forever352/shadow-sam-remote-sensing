## 第 1 页 · 封面

### 项目名称
**基于方向提示与 SAM 的遥感影像阴影检测方法研究**
- 这是申报书里的正式项目名，答辩时不要改成方法名。
- “方向提示”在项目里落地为“由阴影物理先验自动生成的提示”；主链路用框提示，显式方向先验模块作为探索线单独评估。
- “SAM”指 Segment Anything Model，见第 4/7 页。

### 一句话介绍项目
用传统图像处理先找出“可能是阴影”的区域，把这些区域变成 SAM 能读的框提示，再用 LoRA 低成本微调 SAM，把边界修准，最后输出可直接进 GIS 的阴影矢量。

## 第 2 页 · 问题与挑战

### 遥感影像 ★
- 由卫星或飞机从高空拍摄的地表影像，常见 RGB、多光谱、高光谱等。
- 与普通照片的区别：俯视、尺度大、地物类别多、光照和传感器变化大。
- 本项目的输入是航空/卫星影像，输出是逐像素阴影掩膜/矢量。

### 阴影检测 ★
- 判断影像中每个像素是不是阴影，输出一张二值掩膜（阴影=1，非阴影=0）。
- 阴影本身不是地物，而是遮挡体（建筑、树木、云等）挡住阳光形成的暗区。
- 难点：阴影与水体、深色植被、深色路面、蓝色屋顶在光谱上接近，容易“异物同谱”。

### 语义分割 vs 实例分割
- **语义分割**：只区分像素类别，不区分同一类里的不同个体（所有阴影都是同一类）。
- **实例分割**：在语义分割基础上区分不同个体（阴影 A、阴影 B）。
- 本项目主任务是语义分割；Mask R-CNN 是实例分割基线，所以输出形式略有差异。

### 二值掩膜（mask）
- 一张与影像同尺寸的图，每个像素取 0 或 1（或 0/255）。
- 本项目的 GT（真值）掩膜中，阴影为 1，非阴影为 0。
- 评估指标（IoU、BER 等）都是在掩膜上计算的。

### 传统阈值法
- 直接根据颜色/亮度设定一个阈值，低于阈值的像素判为阴影。
- 优点：无需训练、快；缺点：阈值对光照、季节、传感器、地物类型敏感，换场景就要重调。

### SAM 零样本 ★
- **零样本（zero-shot）**：不针对下游任务训练，直接拿预训练模型推理。
- SAM 没在“遥感阴影”上训练过，所以直接用它分割阴影效果有限；本项目的零样本基线 IoU 只有 0.3480。
- 这也是为什么要微调。

## 第 3 页 · 评估基座

### 数据泄漏 / 同源泄漏 ★★
- 训练集和测试集里出现了同一来源、同一场景的影像，模型“见过”测试场景，指标会虚高。
- AISD 自带 Test51 与 Train412 的 43 个原始大图基名中有 42 个重叠；51 张测试图里 50 张来自训练场景。
- 这不是模型能力强，而是评估口径有问题；所以本项目重建了无泄漏划分。

### 按原始大图基名划分 ★
- AISD 的一张原始大图会被裁成多张子图；如果随机按子图划分，同一张大图的子图会同时出现在训练和测试里。
- 正确做法：按“原始大图基名”整组划分，保证同一张大图只出现在一个集合。
- 本项目重划为 **68 训练 / 16 验证 / 21 测试** 张原图，对应 **262 / 58 / 92** 张子图；三集基名不重叠。

### 训练集 / 验证集 / 测试集
- **训练集**：用来更新模型参数。
- **验证集**：用来选超参数、选最佳 checkpoint（best-val）。
- **测试集**：只在最后报告一次，不参与任何选择。
- 本项目测试集是 92 张子图 / 21 个独立原始场景。

### 基线（baseline）
- 用来对比的参照方法。本项目包括 U-Net、SegNet、Mask R-CNN、冻结编码器 SAM、零样本 SAM、Otsu/C3I 等。
- 基线必须在同一数据划分、同一评估脚本下重训，否则数字不可比。

### 数据增强 bug
- 早期 U-Net/SegNet 脚本里，图像和掩膜各自独立随机翻转，导致图像翻了、掩膜没翻，标签错位。
- 修复后重新训练，保证输入和标签同步变换。

## 第 4 页 · 全自动链路

### 物理先验
- 不依赖学习、根据物理/图像常识设计的规则。
- 本项目的物理先验：阴影在灰度图上局部偏暗；用 CLAHE 增强暗部、Otsu 分暗区、形态学去噪。
- 作用：把搜索空间从整图缩小到“高召回候选区”，降低 SAM 误分割。

### 高召回（high recall）
- 召回率高 = 宁可多找一些，也尽量不漏掉真阴影。
- 粗提取的目标是高召回，不追求边界精确；边界交给 SAM。
- 代价是会有一些误检，后续由 SAM 和面积过滤处理。

### 全自动 / 无需人工点选
- 传统 SAM 使用需要人点一下或画个框；本项目用算法自动生成框提示，不读 GT，不需要人工交互。
- 这是工程上的关键优势：可以批量处理影像。

### 矢量输出
- 把二值掩膜转成多边形（GeoJSON / Shapefile），可直接导入 QGIS、ArcGIS 等 GIS 软件。
- 相比栅格掩膜，矢量更方便编辑、量算面积、叠加其他图层。

## 第 5 页 · 物理粗提取

### 灰度图
- 把 RGB 三通道按亮度加权成单通道；阴影在灰度上表现为低亮度。
- 灰度化会丢失颜色信息，但对“暗区”检测够用。

### CLAHE ★
- **Contrast Limited Adaptive Histogram Equalization**，限制对比度自适应直方图均衡化。
- 普通直方图均衡化容易把噪声放大；CLAHE 分小块做均衡，并限制对比度，能增强暗部细节而不过曝。
- 本项目的 CLAHE 用来让阴影内部的纹理更清楚，便于后续阈值分割。

### Otsu 阈值 ★
- 一种自动选阈值的方法：遍历所有阈值，选让“前景/背景类间方差最大”的那个。
- 不需要人工设定阈值，比固定阈值更稳。
- 本项目对“反相图”做 Otsu：先把亮暗翻转，让阴影变成亮区，再分割。

### 形态学开运算
- 先腐蚀后膨胀，用来去掉小噪点、细连接，保留较大的阴影块。
- 本项目的开运算用于去掉路面细碎暗线等噪声。

### 连通域 ★
- 二值掩膜中相互连通的像素组成一个“连通域”（connected component）。
- 每个连通域可能是一块阴影；本项目过滤面积小于 300 像素的连通域，减少碎片。
- 连通域分析还会给出面积、外接矩形、质心等统计量。

### 轴对齐包围框（axis-aligned bounding box）
- 用一个水平/垂直的矩形把连通域框住，不旋转。
- 本项目把这个框作为 SAM 的框提示；框提示同时编码位置和尺度。

## 第 6 页 · 框提示与 SAM 精修

### 提示（prompt）
- SAM 的输入除了图像，还需要“提示”告诉它分割哪里。
- 常见提示：点（point）、框（box）、掩膜（mask）、文本（text，需额外模型）。
- 本项目用框提示；也实现了点提示/方向点提示作为对照。

### 框提示 vs 点提示
- 框提示给出目标的大致范围和尺度，对大面积阴影更稳；点提示只给一个位置，容易歧义。
- 框提示可以直接复用 SAM 的提示编码器，不需要额外的提示学习网络。

### 提示编码器 / 掩膜解码器
- SAM 结构：图像编码器（ViT）提特征；提示编码器把点/框编码成向量；掩膜解码器融合两者，输出掩膜。
- 本项目训练时冻结图像编码器的大部分权重，只通过 LoRA 注入低秩更新，同时训练提示编码器和掩膜解码器。

### 逐框分割后取并集
- 一张图可能有多个框；SAM 对每个框输出一个掩膜，最后把所有掩膜取并集。
- 并集可能出现重叠/碎片，本项目用面积过滤和矢量化后处理。

### TP / FP / FN
- **TP（True Positive）**：预测为阴影，实际也是阴影。
- **FP（False Positive）**：预测为阴影，实际不是（误检）。
- **FN（False Negative）**：实际是阴影，但没预测出来（漏检）。
- 误差图里 TP 绿、FP 红、FN 蓝。

## 第 7 页 · LoRA 微调

### 全量微调 vs 参数高效微调 ★
- **全量微调**：更新模型所有参数；显存大、训练慢、小数据集容易过拟合。
- **参数高效微调（PEFT）**：只训练少量新增参数，冻结大部分预训练权重。
- LoRA 是 PEFT 的一种。

### LoRA ★★
- **Low-Rank Adaptation**：在 Transformer 的线性层旁挂两个小矩阵 A、B，用低秩乘积近似权重更新。
- 原权重 W 冻结，只训练 ΔW = B·A；秩 r 通常取 4/8/16。
- 本项目 r=8，LoRA 参数约 0.44M；加上提示编码器/掩膜解码器，总可训练 4.51M，占总参数 93.7M 的约 4.8%。

### 为什么 LoRA 适合本项目
- 8GB 笔记本 GPU 显存有限，全量微调不现实；
- 训练集只有 262 张，低秩适配能降低过拟合风险；
- 迁移成本低，权重文件小，便于交付。

### ViT-B
- Vision Transformer Base，SAM 的图像编码器骨干，约 93.7M 参数。
- 它把图像切成 patch，经过多层自注意力提特征；LoRA 挂在注意力层的 qkv/proj 线性层上。

### Focal Loss / Dice Loss
- **Focal Loss**：降低易分类样本的权重，缓解阴影/背景像素不平衡。
- **Dice Loss**：直接优化预测掩膜与 GT 的重叠程度，对类别不平衡不敏感。
- 本项目用两者相加。

### AMP / AdamW / 余弦退火
- **AMP（自动混合精度）**：用 fp16/bf16 加速、省显存。
- **AdamW**：常用优化器，带解耦权重衰减。
- **余弦退火**：学习率按余弦曲线从初始值降到 0，训练更稳定。

## 第 8 页 · 实验设置

### 主口径 / 无泄漏口径
- 本项目所有主结果都在重划的 68/16/21 无泄漏划分上报告。
- “主口径只有一个”是为了避免同一张表混用不同划分。

### best-val
- 每个 seed 训练多个 epoch，只在验证集上按 IoU 选最佳 checkpoint；测试集不参与选模型。
- 这样可以避免“用测试集调模型”的隐性泄漏。

### IoU ★★
- **Intersection over Union**：预测掩膜与 GT 的交集 / 并集。
- 取值 0–1，越大越好；本项目主结果 IoU 0.7990（3 seed 均值）。
- 直观理解：预测和真值重叠得越多，IoU 越高。

### BER ★★
- **Balanced Error Rate**：BER = (FPR + FNR) / 2，即误检率和漏检率的平均。
- 取值 0–1，越小越好；它同时惩罚误检和漏检，比 OA 更适合不平衡数据。
- 本项目主结果 BER 0.0612（3 seed 均值）。

### F1 / OA / Precision / Recall
- **Precision（精确率）**：预测为阴影的像素里，真正是阴影的比例。
- **Recall（召回率）**：真实阴影像素里，被预测出来的比例。
- **F1**：Precision 和 Recall 的调和平均。
- **OA（Overall Accuracy）**：所有像素里预测正确的比例；阴影占比低时 OA 容易虚高。

### FPR / FNR
- **FPR（False Positive Rate）**：非阴影被误判为阴影的比例。
- **FNR（False Negative Rate）**：阴影被漏判的比例。
- 本项目 seed-0 的 FPR 0.0405、FNR 0.0882，漏检约为误检的 2.2 倍。

### macro / pooled / scene
- **macro**：先逐图算指标，再对图取平均；本项目主表用 macro。
- **pooled**：把所有像素合在一起算一个指标。
- **scene**：先按原始场景聚合，再对场景取平均；测试集 21 个独立场景。
- 三种口径可能给出不同数值，报告时要写清楚。

### 3 seed
- 用 3 个随机种子各训练一次，报告均值±标准差，减少“单次运气”的影响。
- 本项目主表是 3 seed 均值；部分对照是单 seed，已标注。

## 第 9 页 · 主结果

### 0.7990 / 0.0612 / 0.8869 怎么读
- IoU 0.7990：预测阴影和 GT 的平均重叠度约 80%。
- BER 0.0612：误检率和漏检率的平均约 6.1%。
- F1 0.8869：精确率与召回率的调和平均约 88.7%。
- 三个数都是 3 seed 均值，测试集 92 张 / 21 个独立场景。

### “数值上高于” ★★
- 本项目只说“数值上高于”三个全监督基线，不说“显著超越/SOTA”。
- 原因：测试集只有 21 个独立场景；未做多重比较校正；效应量随口径变化。
- 答辩时如果被问“你们是不是超过了 U-Net”，可以回答：在同一无泄漏划分、同一评估脚本下，3-seed 均值和逐图配对都支持数值优势；但样本规模有限，我们不把它升级为 SOTA 声明。

### 87/92 图胜、21/21 场景 BER 更低
- 3 seed 对 3 seed 的逐图配对：LoRA 在 92 张图里有 87 张 IoU 高于 Mask R-CNN。
- 按 21 个独立场景聚合：LoRA 在 21 个场景里 BER 都更低（描述性统计）。
- 这些是“数值优势”的证据，不是显著性声明。

## 第 10 页 · 3-seed 配对

### 配对检验 / t 值
- 配对检验：同一张图/同一个场景上比较两个方法的差值，而不是比较两组独立样本。
- t 值越大（绝对值），说明差值相对波动越明显；本项目报告 t 值只作描述性统计。
- 没有做多重比较校正，所以不把 t 值当作“显著”的最终证据。

### 为什么图级和场景级都要看
- 同一场景的子图高度相关，按 92 张图统计会夸大独立样本量。
- 按 21 个场景聚合更保守；两种口径都给，避免只挑有利口径。

### 效应量随口径变化
- pooled / macro / scene 三种聚合下，LoRA 相对 U-Net 的 IoU 优势约为 +0.005 / +0.035 / +0.050（seed-0 示例）。
- 方向一致，但量级不同；所以报告里写“数值上高于”，不写“显著超越”。

## 第 11 页 · 消融

### 消融实验（ablation）
- 控制变量，逐步去掉/替换某个模块，看性能变化，回答“增益从哪来”。
- 本项目：零样本 SAM → 冻结编码器 + 训练提示/解码 → LoRA 微调，三者同一提示链路、同一划分。

### 零样本 / 冻结编码器 / LoRA
- 零样本 IoU 0.3480：完全不微调，SAM 不懂遥感阴影。
- 冻结编码器 IoU 0.5621：只训练提示编码器和解码器，编码器不适配。
- LoRA IoU 0.7990：编码器通过低秩适配遥感域，提升最大。
- 结论：关键不是“换提示”，而是“让编码器适配”。

### 92/92 张、91/92 张
- 零样本 → LoRA：92 张图全部变好（seed-0 逐图配对）。
- 冻结 → LoRA：91/92 张更高。
- 这些是逐图配对结果，不是统计显著性声明。

### 可训练参数 4.51M 的构成
- LoRA adapter 约 0.44M；
- prompt encoder + mask decoder 约 4.07M；
- 合计 4.51M，占总参数 93.7M 的约 4.8%。
- 所以不能说“只训了 LoRA”；是“LoRA + 提示/解码器联合训练”。

## 第 12 页 · 跨数据集与误差

### 跨数据集零样本迁移
- 在 AISD 上训练，直接在 RSISD 上测试，不微调。
- 本项目 RSISD test200 的 IoU 0.7842（seed-0）。
- 但 RSISD 任务较容易：传统 Otsu 就能到 0.5711，所以不能把 0.7842 读成“泛化很好”。

### 域差（domain gap）
- 训练域和测试域的传感器、分辨率、光照、地物分布不同，导致性能下降。
- AISD 是航空影像，RSISD 是另一套遥感数据；跨域结果只作参考，不作泛化结论。

### 误检 / 漏检
- 误检（FP）：把非阴影判成阴影；漏检（FN）：阴影没判出来。
- 本项目主误差在召回侧：漏检约为误检的 2.2 倍。

### 小连通域召回
- 面积小于 256 像素的阴影连通域，平均召回率 0.538，说明小阴影容易漏。
- 但按“漏检像素量”统计，面积 ≥4096 像素的大连通域贡献了 39.0% 的漏检像素。
- 两种口径结论不同：小阴影“数量上难”，大阴影“像素量上贡献大”。

### 边界带 F1
- 在 GT 边界附近 r=1/3/5 像素的带内计算 F1，分别为 0.745/0.819/0.849。
- 边界越靠近越难；边界是阴影检测的难点之一。

## 第 13 页 · 单图多方法

### n=1 是什么意思
- 只展示一张图的对比，不是统计结果。
- 单图数值只作陈列，不构成方法排序或优劣结论。
- 答辩时如果被问“为什么这张图 LoRA 不是最好”，可以回答：单图受场景影响很大，我们看的是整体 3-seed 主结果和失败模式。

### 失败模式
- 植被、水体、深色路面、蓝色屋顶容易被并进阴影。
- 这也是后续“暗色地物判别”和“跨传感器域适应”的动机。

## 第 14 页 · 软件原型

### 矢量化
- 把二值掩膜转成多边形：用 `rasterio.features.shapes` 提取轮廓，保留孔洞。
- 再用 Douglas–Peucker 简化（默认容差 1.5 像素），按最小面积 64 像素² 过滤碎片。

### GeoJSON / Shapefile
- **GeoJSON**：基于 JSON 的矢量格式，文本可读，适合 Web/GIS。
- **Shapefile**：ESRI 传统矢量格式，由 `.shp/.shx/.dbf` 等文件组成，GIS 软件通用。
- 本项目两种都支持。

### CRS / 地理参考
- **CRS（Coordinate Reference System）**：坐标参考系，如 EPSG:32650。
- 带地理参考的输入：输出地图坐标，并在 GeoJSON 顶层写 `crs`。
- 无地理参考的 PNG/JPG：输出像素坐标，并标记 `coord_system="pixel"`。
- 本项目的地理参考分支用合成 EPSG:32650 样本验证，只证明 CRS 写出路径走通，不代表真实遥感产品的 CRS/轴序已大规模验证。

### 面积差 0.0107% / 栅格化 IoU 0.8438
- 矢量↔栅格往返面积差 −5 像素 / 46614，约 0.0107%。
- 栅格化后 IoU 0.8438，对照管线自身 0.8453，差 −0.00144，来自简化与最小面积过滤。
- 说明矢量化损失很小，但不是零。

## 第 15 页 · 方向先验与 S-EO

### 阴影方向先验
- 阴影由太阳方位角和遮挡体几何决定；理论上，阴影方向可以提供额外线索。
- 旧做法：用阴影连通域的最小外接矩形长轴作为“方向标签”。
- 问题：长轴同时受建筑朝向和太阳方位角影响，单时相数据下模型可能学到建筑朝向，而不是太阳方向。

### 太阳方位角 / 高度角 ★
- **方位角（azimuth）**：太阳在水平面上的方向，通常从北顺时针度量。
- **高度角（elevation）**：太阳离地平线的高度。
- S-EO 提供真实太阳角；AISD 没有太阳角真值。

### cos2θ / sin2θ、二倍角
- 阴影方向是“轴”不是“箭头”，180° 周期；直接用角度回归会有 0°/180° 跳变。
- 用 (cos2θ, sin2θ) 表示方向，把 180° 周期变成 360° 的普通向量；角度误差 = acos(向量点积)/2。

### 圆形均值
- 对角度求平均不能直接算术平均（0° 和 180° 平均会出错）；要把角度转成单位向量再平均，再取角度。
- 本项目的常数基线、方向标签聚合都用圆形均值。

### 四种方向注入
1. **几何方向过滤**：用连通域主轴/最小外接矩形估计方向，过滤方向杂乱的暗色地物。
2. **方向点提示**：用旋转框角点或主轴采样点替代轴对齐框。
3. **方向点训练**：把方向点提示用于 SAM 训练。
4. **方向 Adapter**：把方向向量条件注入提示编码器。

### 翻转自监督 / 方向回归头 / DTICT
- **翻转自监督**：把图像水平翻转，让模型判别翻转方向，理论上迫使骨干编码方向信息。
- **方向回归头**：在骨干后加一个 2 维回归头，输出 (cos2θ, sin2θ)。
- **DTICT**：一种噪声抑制/一致性训练思路（参考祁昆仑等 2025），本项目做了简化重构。

### S-EO 数据集
- 一个带真实太阳角和几何阴影掩膜的遥感数据集；本项目只用了小子集（OMA 42 日期 + JAX 4 AOI × 25 日期）。
- OMA 是 0.3 m RGB；JAX 是 1.2 m 4 波段 MSI。
- 方位角只覆盖 108–171°，不是 360° 全向。

### AOI
- **Area of Interest**，感兴趣区域。JAX 有 4 个 AOI，每个 AOI 25 个日期。

### 留一日期（LOOCV）/ 留一 AOI（LOAO）
- **LOOCV**：每次留出 1 个日期，其余日期训练，评估留出日期；用来检验“同一 AOI、跨日期”的可复现性。
- **LOAO**：每次留出 1 个 AOI，其余 AOI 训练，评估留出 AOI；用来检验“跨场景”信号。
- 两者都不是最终独立测试集；结论只作 pilot 层面描述。

### 常数基线 / 高程-only oracle ★★
- **常数基线**：所有图都预测训练集标签的圆形均值；“什么都不学”的水平。
- **高程-only oracle**：只用真实太阳高度角做二次多项式回归预测方位角；它使用了真值高度角，是“高程捷径”的上界。
- 为什么要这两个基线：S-EO 里方位角和高度角强相关（OMA r=−0.69，JAX r=−0.88）；如果模型只是学会“高度角→方位角”，也会看起来不错。所以必须和 elevation-only oracle 比。

### 标签打乱对照
- 把训练标签随机打乱后重训，评估留出图；如果模型仍很好，说明它在拟合标签分布/记忆训练集。
- 打乱对照的期望误差接近常数基线，不是 45°。

### sign-flip / 日期块检验
- **sign-flip 置换检验**：对配对差值随机翻转符号，看观察到的均值差是否极端；折间相关，p 只作描述性证据。
- **日期块**：把连续日期分成若干块，在块级做 sign-flip，缓解同一 AOI 内日期相关导致的假显著。

### 支撑内 / 支撑外
- 源域方位角范围 [min, max] 是“支撑”；目标图方位角落在范围内叫支撑内，否则叫支撑外。
- 跨域成功线只在支撑内定义；支撑外只描述，不设成功线。

### 预注册 / kill criterion
- **预注册**：先写清 split、指标、判据、停止条件，再跑实验，避免事后挑结果。
- **kill criterion**：如果达到某个失败条件就停止，不继续下游。
- 本项目 S-EO pilot 的判据：必须显著优于常数基线 + 高程-only oracle + 标签打乱对照；否则停止，不接 AISD 下游。

### 本页数字怎么读 ★★
- OMA 同 AOI：模型 2.99°，常数 5.75°，高程 oracle 3.96°；点估计更好，但日期块 p=0.186 未过主门槛 → **未达阳性判据，只能作探索性/不确定**。
- JAX 留一 AOI：模型 11.92°，常数 13.67°，高程 4.16°；4 折描述性，p vs 常数 0.24、vs 高程 0.12 → **无跨场景证据**。
- 双向跨域：支撑内模型未优于源域常数与目标高程 oracle → **无阳性**。
- 旧标签：掩膜长轴与真实太阳角中位差 33.97°（逐连通域口径 B）→ 支持“旧标签混入建筑朝向”的动机，但不能单独证明 AISD 失败原因。

## 第 16 页 · 结论与边界

### 本项目的主要贡献
1. 全自动链路：物理粗提取 → 自动框提示 → LoRA-SAM → 矢量输出。
2. 无泄漏评估基座：发现 42/43 同源泄漏，修复基线翻转 bug，重划 68/16/21。
3. 受控技术演进：零样本 → 冻结 → LoRA，92/92 张变好。
4. 工程原型：GeoJSON/SHP，三条分支验证。
5. 方向先验：四种注入 + S-EO 预注册试点，未观察到稳健跨场景信号，未进入主链。

### 边界 ★★
- 21 个独立测试场景，属于中等规模、单数据集为主的实证结论。
- 主方法 BER 6.12%，没有达到 5% 以下；4.82% 是“3-seed 集成 + flip TTA + 阈值 0.25”的变体，不是主方法。
- 未复现真正的阴影检测 SOTA；ShadowFormer 是阴影去除，指标不可比。
- 软件原型只在单张 512×512 子图与合成 CRS 上验证。
- 方向模块是负/不确定结果，不等于“方向先验无效”。

### SOTA
- **State of the Art**，当前最好水平。本项目不宣称 SOTA，只报告同划分下的数值结果。

### 软著 / 论文
- 软件著作权说明书初稿已完成，尚需按最终 3-seed 结果与现行脚本/模块表更新后提交。
- 学术论文尚未产出；本项目不把“推进中”写成“已完成”。

## 附录 A · 答辩常见追问（建议背下来）

1. **你们和 U-Net 比公平吗？**
   - 同一无泄漏划分、同一评估脚本、同一测试集；U-Net/SegNet/Mask R-CNN 都是 3 seed 重训。Mask R-CNN 输入分辨率有差异（512 上采样到 800，SAM 类走原图 1024），我们在报告里明确写了“仅部分缓解”，不宣称对比完全公平。

2. **为什么不用全量微调 SAM？**
   - 8GB 笔记本 GPU 显存不够；262 张训练图全量微调容易过拟合；LoRA 只训 4.8% 参数，效果更好且可交付。

3. **为什么 BER 没到 5%？**
   - 主方法 BER 6.12%；5% 以下是通过“3-seed 集成 + flip TTA + 阈值 0.25”的变体达到 4.82%，但 IoU 下降、FPR 升高，且是 110 个候选中按验证集选的变体，不是主方法。我们不把变体说成主方法达标。

4. **方向模块为什么没进主链？**
   - 四种注入在同族无方向对照下 IoU 差异 ≤0.0007；方向 Adapter 的 BER 效应可被随机方向对照复制；方向回归头误差接近常数预测器。S-EO 真实太阳角试点也未达到阳性判据。所以方向模块作为诊断线保留，不进入主方法。

5. **S-EO 试点是不是说明方向先验没用？**
   - 不能。试点只覆盖单 AOI、42 个日期、JAX 4 折、224 输入；结论是“当前协议下未观察到稳健跨场景信号”，不是“方向先验普遍无效”。

6. **你们最大的创新点是什么？**
   - 不是发明新网络，而是把“物理先验 + 自动提示 + LoRA + 矢量交付”做成一条可在 8GB GPU 上跑通、可复核的全自动链路；同时发现并修复了评估基座的同源泄漏与增强 bug。

7. **21 个场景够吗？**
   - 对于结题规模够做实证，但不足以做跨传感器/跨大洲的泛化声明；我们在报告里明确限定。

8. **跨数据集 0.784 是不是说明泛化好？**
   - 不能。RSISD 任务较容易，Otsu 都能到 0.571；跨域只作参考，不作泛化结论。

9. **为什么用框提示而不是点提示？**
   - 框提示同时编码位置和尺度，对大面积阴影更稳；点提示容易歧义。框提示还可以直接复用 SAM 的提示编码器。

10. **软件原型能直接用吗？**
    - 可以处理单张 GeoTIFF/PNG，输出 GeoJSON/SHP；但只在单张 512×512 子图和合成 CRS 上验证，真实多传感器批处理还需要继续测试。
